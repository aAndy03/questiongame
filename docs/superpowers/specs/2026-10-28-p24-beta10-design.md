# P24 — beta.10: our own title bar, Stage you can trust, a guided start

## Why

The maintainer's list after beta.9. Three themes:

- **The window is ours.** Studio's header already carries the back/forward
  buttons, the play pill, Control's tools and the operator; the OS title bar
  above it is a second, empty band. Studio draws one bar, with the window's
  own controls, on Windows and macOS — and a setting gives the native bar
  back.
- **Stage goes where it is told, and closes when it is told.** A friend on a
  Mac (an iPad connected, then AirPlay mirroring to an Apple TV) saw Stage
  open on the laptop or not at all. On Windows, closing Stage from Alt-Tab
  left Studio saying Stage was still open; and Studio has no *Close Stage* at
  all.
- **A new operator is not left alone.** A 1.1.1 user upgrading to 2.0 meets a
  bare "Name your workspace"; Control's empty state is a dead end; and there
  is no place that explains the game or the app.

## Scope

beta.10 takes items 1–5 and 6.1 (+ the shortcuts list, 6.2.3). **The tips
system (6.2–6.7) moves to beta.11**: it is a system of its own — when to show
what, how often, how it learns what the operator already knows — and it reads
from what beta.10 builds (the Help page's topics, the gestures registry, the
key/gesture badges). Designing it after those exist is cheaper and better.

## What the research found (the causes)

From the codebase (file:line in the research notes) and the Tauri 2.12.4 / tao
0.37.1 sources:

1. **No window-close handling for Stage, mirrors or Statistics.** The only
   `on_window_event` is the quit guard on `main`. A window the OS closes
   (Alt+F4, Alt-Tab, the taskbar, Cmd+W) is gone, the host's `StageDisplay.on`
   is not cleared, and no `monitors-changed` follows; Studio's displays are a
   snapshot of the last event. A closed mirror is even reopened by the next
   reconcile. The inverse too: `play_load` / `stage_open` create Stage and
   emit nothing, so the strip can say "no Stage" when there is one.
2. **macOS, mixed scale (confirmed in tao).** `move_to` sets a *physical*
   position taken from the target monitor (converted with the target's
   scale) and tao converts it back with the window's current scale (the
   primary's). Retina laptop + a 1× TV/AirPlay display or a Sidecar iPad:
   the window lands inside the primary, and `set_fullscreen(true)` (current
   screen) fullscreens it there.
3. **macOS fullscreen is asynchronous (tao queues requests during the
   animation).** `move_to` does `set_fullscreen(false)` → `set_position` →
   `set_fullscreen(true)` at once; for a window built `.fullscreen(true)` the
   middle step is lost and Stage stays on the primary.
4. **macOS monitor names are `Monitor #<model>`**, so keys collide between
   displays of one model/resolution, and virtual displays (Sidecar, AirPlay)
   are plausible collisions → `Ambiguous`, or the first match taken.
5. **A mirrored display is invisible.** CoreGraphics lists a mirror set once:
   an Apple TV in *Mirror* mode is not a display the app can use, and nothing
   says so (Windows has the `alsoOn` hint; macOS has nothing).
6. **Silent failure.** `move_to` returns `Ok` when the monitor is not found,
   after `stage_set_monitor` has already saved the pick: Studio says "Stage on
   TV" while Stage is on the laptop.
7. **No `stage_close`.** The pacer's tick is disabled; mirrors can be removed
   but Stage itself never closed.
8. **The shortcuts list** is Control's chords only; the gestures added since
   1.1 (Shift/Ctrl+click, Ctrl-drag, Escape to cancel a drag, Shift+Arrow on
   Screens…) are nowhere.

## §1 Our title bar

- **Default: custom; a setting gives the native bar back** — *Settings ▸
  General ▸ Window: Use the system title bar* (off). Applied **live** by the
  host (no restart): Windows `set_decorations`, macOS `set_title_bar_style`
  (runtime since Tauri PR 9788). Studio reads the same setting to draw or
  drop its own controls. The JS side never gets `set-decorations`: the host
  applies the setting, so the permission stays off the webview.
- **One bar.** The sidebar's brand row and the TopBar are already 48px; they
  read as one bar. Every empty part of it is a **drag region**
  (`data-tauri-drag-region` on the bar and its non-interactive children);
  double-click maximizes/restores (Windows) or zooms (macOS), as the native bar.
  The play pill stays centred on the window.
- **Windows:** `decorations: false`, `shadow: true` (the 1px edge and Win11
  rounded corners, resize borders kept). Minimize · Maximize/Restore · Close
  at the far right of the bar, 46×48 like Windows' own, Close red on hover;
  the maximize icon follows the window (`onResized` + `isMaximized`); hidden
  in fullscreen. **Snap Layouts on hover of our maximize button is not
  available in Tauri** (it needs the button to be the OS's own); dragging to
  the edges, Win+Arrow and Win+Z still snap. A plugin that fakes it exists;
  see Decisions.
- **macOS:** decorations kept, `titleBarStyle: Overlay` + `hiddenTitle`:
  the **native traffic lights stay** (close, minimize, zoom, full screen,
  their hover menus), the content runs under them, the sidebar's brand row
  leaves them 76px. No custom buttons on macOS.
- **Close goes through the quit guard** (`close()`, never `destroy()`), as
  the native close box does today.
- The window's title stays set (taskbar, Alt-Tab, Mission Control, e2e).
- Capabilities (`operator.json`, `main` only): `core:window:allow-minimize`,
  `allow-toggle-maximize`, `allow-close`, `allow-start-dragging`,
  `allow-internal-toggle-maximize` (the drag region's double-click),
  `allow-is-maximized`, `allow-is-fullscreen`, the window events' listen.
  Stage and Statistics get nothing new.

## §2 Stage goes where it is told

**What the friend saw, exactly** (the maintainer, after asking): with the
iPad disconnected, he started AirPlay screen mirroring to the TV (wireless,
not HDMI); Stage opened on the laptop's display, and he **dragged it to the
TV by hand**. So the TV was a usable display (macOS let the window move
there) and Stage was simply put on the wrong one — by the remembered display
(the iPad) being gone and Stage falling back to the primary, and/or causes
2–3 above (scale, the fullscreen race). And after his drag, Studio still
believed Stage was on the laptop.

- **Stage follows a hand move.** When a Stage window (or Statistics) is
  moved to another display by hand — dragged, Win+Shift+Arrow, the macOS
  window menu — the host sees it (`WindowEvent::Moved` → the window's
  `current_monitor()`), makes that display Stage's (the pick saved, fullscreen
  there) and emits `monitors-changed`; Studio's ticks follow. A hand move is
  an answer, not an error.
- **When the remembered display is gone**, Stage still falls back to the
  primary, but the notice now names it and offers the displays there are:
  *Living Room TV was not found; Stage is on Built-in display* · *Move to
  Living Room* (when exactly one other display exists) · *Monitors settings*.
- **A display that appears while Stage is on the fallback** (AirPlay
  connecting a few seconds after Load): if it is the remembered one, Stage
  goes back to it (today's `restored` path, now through the new placement).

- **Placement, rewritten (`windows.rs move_to`, Stage and Statistics alike):**
  leave fullscreen and **wait** for it (the window's `Resized`/fullscreen
  state, with a timeout), move in **logical coordinates of the target
  monitor**, then `set_fullscreen_on_monitor` (Tauri 2.12) with a point inside
  the target; a new Stage is built windowed at the target, then made
  fullscreen. **Verify**: after the transition, read the window's
  `current_monitor()`; if it is not the target, retry once; still not → a
  notice (*Stage could not move to TV; it is on Built-in display*, actions:
  *Try again* · *Monitors settings*), and the saved pick is the display Stage
  is really on. The pick is saved **after** a placement that took, never
  before.
- **macOS displays get names and an identity** — a small macOS topology
  reader (as `topology.rs` is for Windows): per display its localized name
  (*LG UltraFine*, *Sidecar Display*, *Living Room*), whether it is part of a
  mirror set, and whether the "Displays have separate Spaces" option is off.
  The key becomes `<name>@WxH`, with the old `Monitor #N@WxH` keys still
  matched once (remembered picks survive the update).
- **What the operator is told (Studio):** on macOS, a display mirrored by
  another (an Apple TV in AirPlay *Mirror*) is shown in the displays list as
  *Mirroring Built-in display — choose Use as Separate Display to put Stage
  there*; with separate Spaces off, a notice says full-screen Stage on a
  second display needs *Displays have separate Spaces* on, with *Open
  System Settings* (`x-apple.systempreferences:` URL) · *Dismiss*.
- **A display report**: *Settings ▸ Monitors ▸ Copy display report* copies a
  plain text of what the host sees (each display's name, key, size, scale,
  position, primary, mirror set; where Stage and Statistics are, really) —
  for a friend's bug report, since nobody here owns every setup.
- macOS and Windows behaviour is unit-tested on the pure parts (keys, mirror
  sets, the verify-and-retry policy); the macOS window path itself cannot be
  run here — it needs a Mac (the friend), and the report is how we will hear.

## §3 Closing Stage

- **The host hears every Stage, mirror and Statistics window close**
  (`WindowEvent::Destroyed`, whoever closed it): it updates `StageDisplay`
  and emits `monitors-changed`. Stage closed by the OS: if mirrors remain,
  the first becomes the pacer (Stage is still up); if none, Stage is closed
  — no notice (the operator closed it), and *Open Stage* reopens it where it
  was. A mirror closed by the OS is dropped from the mirrors (not reopened
  by the next reconcile). Statistics closed by its close box: *Show
  Statistics* again.
- **`stage_close`** (Studio only): closes every Stage window. The remembered
  display is kept, so *Open Stage* puts it back. A Play keeps playing (the
  Viewer still shows it); Control's top strip shows *Open Stage* while it is
  closed.
- **The ticks become whole**: the pacer's tick can be unticked — with mirrors,
  the first mirror takes over; alone, Stage closes. `stage_remove_display(key)`
  in the host does all three (mirror, pacer with mirrors, last one).
- **Where to close it:** the displays popover header gets *Close Stage* (icon,
  beside *Open Stage*); Settings ▸ Monitors gets *Close Stage* beside *Open
  Stage*.
- `play_load` and `stage_open` emit `monitors-changed`, so the strip never
  says "no Stage" while one is up.

## §4 A 1.1.1 library meets 2.0

`NameWorkspacePage` in its *name* mode (a library that already holds teams,
games, an operator) becomes a guided screen:

- **What happened, first:** *questiongame 2.0 keeps your library in a
  workspace.* Then three short points with icons: **Your library is safe** —
  it was copied before anything changed (the backup's file name, a *Show in
  folder* link); **Everything is here** — counts of teams, domains,
  questions and games, as a small card that is the workspace; **Why
  workspaces** — keep a club, a classroom and a TV show apart, copy or move
  rows between them.
- **Then the one thing to do:** the name field, **prefilled** (*My library*,
  or the operator's name + *library*), with *You can rename it any time in
  Manage workspaces.* and *Continue*.
- The fresh-install *create* mode stays short, with the same card (empty).

## §5 Control with nothing loaded

The empty state becomes **Pick up where you left off**: up to six games, the
most recent first — by the later of when it was last **played** (its Plays'
start/end) and last **edited** — each a card with its name, folder, team
and question counts, *Played 2 days ago* / *Edited yesterday*, and **Load
into Control**. *Go to Games* stays, as the secondary action under the list.
With no games at all: the current empty state (*Go to Games*, *New game*).

## §6.1 Help, and the shortcuts list (6.2.3)

- **A Help page**, a sidebar entry at the bottom beside Settings (`F1` opens
  it too). Sections, each a few short paragraphs with visuals:
  **How the game plays** (teams, the token, choosing a domain, the
  easy→hard walk, Select → Lock → Reveal, scoring, the round rule, the
  end); **Prepare a show** (teams, domains and questions, games: roster,
  board, rules); **Your library** (search, filters, groups and tags, drag
  onto a domain and Ctrl to move, selection gestures, import with the AI
  template, share, workspaces); **Run a show** (Control, Stage and the
  displays, Statistics, rehearsal); **Displays** (macOS: separate Spaces,
  AirPlay *Use as Separate Display*, Sidecar; Windows: Extend, not
  Duplicate); **Shortcuts and gestures**.
- **Visual components** made for it and kept for beta.11's tips: `KeyBadge`
  (a key chord: `Ctrl` `Shift` `Z`, ⌘ on a Mac), `GestureBadge` (a mouse/
  trackpad gesture: *Ctrl + drag*, *Shift + click*, with a small icon),
  `HelpFigure` (a captioned mini-picture: a domain row being dropped on, the
  Select → Lock → Reveal steps).
- **One registry of gestures** (`gestures.ts`): every fixed gesture with its
  keys, where it works and what it does. The Help page and **Settings ▸
  Shortcuts** read it: the editor gets a read-only *Mouse and keyboard
  gestures* group under Control's chords. A test fails when a gesture's
  handler names a key the registry does not.
- English only, like the rest of Studio's UI (What's new stays EN+RO).

## §7 Tests

Host: the window-close policy (pacer alone → closed; pacer with mirrors →
promoted; mirror → dropped), `stage_remove_display`, `stage_close`, the
placement verify-and-retry policy and the saved pick only after success,
macOS keys (name + size, legacy key still matched), mirror sets.
Studio: title-bar controls on Windows (buttons, maximize icon follows,
hidden in fullscreen, none on macOS, none with the setting on), drag
regions present, the setting round-trip; the displays popover's whole ticks
and *Close Stage*; the guided workspace screen (prefilled name, counts,
backup line); Control's recent games (order, played/edited words, Load);
Help page sections and the shortcuts editor's gestures group from the
registry. e2e: close Stage from Studio and see it gone; the title bar's
buttons exist on Windows.

## §8 Decisions — please confirm

1. **Tips system → beta.11.** (Recommended; it builds on this version's Help
   content, gestures registry and badges.)
2. **Windows Snap Layouts flyout on our maximize button: not in beta.10.**
   Tauri has no API; a third-party plugin (`tauri-plugin-frame`) fakes it
   with a native child window over the button. Snapping by edge-drag,
   Win+Arrow and Win+Z still works. Could be a beta.11 experiment.
3. **A Stage window closed by the OS is accepted, not prevented** — Studio
   updates and *Open Stage* brings it back where it was.
4. **Help is its own sidebar entry** (not a Settings tab), and `F1`.
5. **The title-bar setting applies live**, no restart.
6. **Statistics' own window keeps the native bar** (it is fullscreen on its
   display almost always).

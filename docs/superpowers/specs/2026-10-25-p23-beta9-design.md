# P23 — beta.9: find it, keep your place, move it, more room

Status: approved 2026-10-25. `main` only (Beta).

## Why

The maintainer works in a big library (the Beta Demo: 1,022 questions, 15
domains, a game with 569 on its board). Three things cost them there: a search
that does not say *why* a row matched, losing their place in long lists and
long Board domains, and putting questions into domains one dialog at a time.
And on every list page the chrome eats height the list needs.

## What the maintainer asked (each item is in a section below)

New
1. Highlight the search query wherever a searched list shows text; make a hit
   in the answers visible, not only in the stem. → §1
2. Stickiness — the Board's open domain, every list's group row and header row,
   table and grid — with smaller variants so it costs little height. → §2
3. Drag questions onto a domain: adds by default, a modifier moves; works for
   one grabbed row and for the selection; no drag handle or any visible
   draggable sign; quick actions gain the same; the result in a toast. → §3

Improvements
1. Content runs down to the status bar on every page (as the Board does);
   pagination padding too large. → §4
2. Pagination moves into the status bar, in a smaller variant, per tab; the
   status bar's own items stay as they are. → §4
3. Less padding in library page templates; remove the page subtitles. → §5
4. The Domains pane's heading and Active/Archived stay fixed; only the domain
   list scrolls. → §5

## §1 Search highlight

- **One highlighter, in the `Text` module** (§2.29 — every readable string
  goes through `Text`): `Text` gains `highlight?: string`. Terms are the query's
  words; matching is case- and diacritic-insensitive (*Pamant* finds
  *Pământ*) and by word prefix (Tantivy matches words, so highlighting
  substrings mid-word would mark what did not match). Matches render in
  `<mark>` styled with a quiet accent tint (`--accent` at low alpha, no
  colour change of the text), legible in both themes.
- **Where:** every list that searches — the library lists (title, subtitle,
  the options line, tag chips), the pickers (*Add teams/domains…*, *Choose
  questions…*), the *Import questions* rows, Workspaces; the opened row's aside
  (`QuestionDetail`: options, explanation, tags) while a search is in force.
- **A hit the row does not show** (the explanation; an option past the
  truncation): the row gets a small muted line *"Found in: explanation"* /
  *"Found in: answers"* so the operator knows why it is there. Decided in
  Studio from the row's own data with the same matcher — no host change
  (the host returns ids and scores, and the row already holds the body).
- Grid cards and table rows alike; nothing highlights without a search.

## §2 Stickiness, cheaply

The rule: **only what tells you where you are sticks, and it sticks at its
smallest.** Every sticky band gets a compact variant (28–32px, 12px type) used
only while stuck, so normal rows keep their size.

- **Lists (table and grid):** the table header row stays stuck at the top (it
  is already `sticky`); **group rows stick under it** (*Astronomie · 11*),
  replaced by the next group as it arrives. In grid view the group row sticks
  the same way. One stuck group at a time; the header row and a group row
  together are at most 64px.
- **The Board:** an open domain's row sticks at the top of the Board while its
  questions scroll under it (name, code, counts, *Choose questions…*, the
  remove button — the full row, at the compact height), and lets go when the
  domain ends. *Open all* and the board summary do not stick.
- **Pickers and the import list:** their group rows stick the same way.
- Variants: `GroupHeader` gains `stuck` (compact, a hairline under it on
  `--background`); `BoardDomainRow` gains the same. Detected with
  `IntersectionObserver` on a 1px sentinel (no scroll handlers), so a stuck
  band can change its look.

## §3 Drag questions onto a domain

- **Grab any question row or card and drag it onto a domain in the Domains
  pane.** No handle, no dots, no hover sign — the row is simply draggable: a
  drag starts after 6px of movement, so a click still opens, Shift/Ctrl+click
  still select, and text is not selected.
- **What moves:** the grabbed row; if it is selected, the whole selection
  (hidden rows included — the selection outlives the view). The drag shows a
  small chip: *"3 questions"*.
- **Drop targets:** the active domains in the pane (not *All questions*, not
  archived ones). The domain under the pointer lights; its name in the chip:
  *"Add 3 questions to History"*.
- **Add (default):** each question joins the domain; those already in it are
  passed (host `AddToDomain` already reports them as `unchanged`).
- **Move (hold Ctrl — ⌘ on a Mac — while dropping; the chip says *"Move 3
  questions to History"* while the key is held):** each question joins the
  target and **leaves every other domain it was in, so it ends in the target
  alone** — whatever the pane shows (the maintainer's call).
- **One write:** a new host bulk edit `MoveToDomain { domain_id }` — one
  transaction, add + leave every other domain (archived ones too), with the
  same report (`changed`, `unchanged`). Like every bulk edit it may leave a
  board with a clash, which Load reports (§2.31) — bulk edits do not refuse
  for boards (*builder's ruling: the design first said "refused whole", which
  no bulk edit does*).
- **Only a release exactly over a domain counts** (the maintainer). Releasing
  anywhere else, or Escape at any point, cancels: nothing is written, no toast.
- **Cues and small motion** (the maintainer; `motion/react`, Studio chrome
  only, honouring reduced motion): the grabbed rows dim while dragged; a chip
  follows the pointer — *"3 questions"*, then *"Add to History"* / *"Move to
  History"* over a target (it changes as Ctrl is pressed or released); the
  domain under the pointer lights (accent tint, ring) and lifts slightly; the
  pane's domains show they accept a drop (a faint outline) while a drag is on;
  a drop pulses the target's count once; a cancel lets the chip fade back to
  where it started.
- **Toast:** *"Added 5 questions to History · 3 were already there"*, *"Moved 8
  questions to Sport"*; a refusal is a notice, as for every bulk edit.
- **Edge cases:** dropping on the domain a question is already in (passed);
  a selection mixing archived questions (archived ones are left out and
  counted: *"2 archived were left out"*); dropping while a search hides some
  selected rows (they go too — the strip counted them); dropping on the
  domain currently picked (Add passes all; Move is a no-op, said); a drop
  outside any domain cancels; Escape cancels mid-drag; a game loaded in
  Control does not block (library edits never touch a snapshot).
- **Quick actions:** the row menu and the strip's *Edit…* gain *Add to
  domain…* and *Move to domain…* (the existing domain picker), so everything a
  drag does has a keyboard way.

## §4 Height: content to the status bar; pagination in it

- **Every page's content runs down to the status bar**, as the Board does: the
  list body (table, grid, pickers aside) is the one scroller and fills to the
  bottom; no bottom padding under it.
- **Pagination moves into the status bar** while a list page is open:
  `PageFooter` gains `variant="status"` (24px, 11px: *1–50 of 1,022* · page
  size · ‹ 1 2 … 21 ›) and renders into a slot on the status bar's right,
  before the clock; the status bar's own items (health, notices, displays,
  clock) stay as and where they are. Each page fills the slot with its own
  list's pagination; a page without a list leaves it empty. Pickers and
  dialogs keep their own footer (they are not the page).
- The slot is a React portal target the status bar owns (`StatusSlot`), not a
  store: nothing about pages lands in a store.

## §5 The page template

- **No page subtitles** on top-level pages (*What gets asked*, *Who competes*,
  …): `PageHeader`'s description goes from every page header; the sidebar's
  hint keeps that text (it is already its accessible description).
- **Tighter template:** the gap from header to content and between toolbar,
  strip and list comes down (24→12px, 12→8px), the header to one line.
- **The Domains pane's head stays put:** *Domains*, the add button and
  *Active · Archived* are fixed; only the list of domains scrolls.

## §6 What must not change

Every existing behaviour: selection rules (beta.8), Shift/Ctrl gestures,
search ranking, Copy to / Move to (workspaces), bulk edits, the Board's walk
and repeated-difficulty rule, the P21 compact sizes, keyboard access. Rows keep
their sizes; only stuck bands are compact.

## §7 Tests

Host: `MoveToDomain` property/unit tests (adds, leaves only the given
domains, passes what is there, refuses a broken board whole). Studio: the
highlighter (diacritics, prefixes, several words, no search → plain); *Found
in*; sticky variant swaps (sentinel mocked); drag → add/move with the toast
counts and the selection; pagination rendered in the status bar per tab and
gone off a list page; subtitles gone; pane head outside the scroller.

## §8 Decisions (answered)

- Decided: a Move leaves every other domain (only in the target); the
  modifier is Ctrl (⌘ on Mac).

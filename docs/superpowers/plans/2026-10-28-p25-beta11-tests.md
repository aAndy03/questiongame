# P25 (beta.11) — test list

Source: `docs/superpowers/specs/2026-10-28-p25-beta11-design.md`. Tests are written first, then the build. Nothing here is run on the author's laptop; CI / the maintainer runs it.

## Conventions followed

- Engine: pure vitest in `apps/studio/src/tips/engine.test.ts`, no React, no `Date.now`. Helpers proposed: `rng(seed)` (seeded random source, a mulberry32-style function returning [0,1)), `clock(startMs)` with `.advance(ms)` / `.advanceDays(d)`, `fresh()` (empty state), `engineAt(state, clock, rng)`. Constants are imported by name from `tips/engine.ts` (`TIP_FLOOR = 0.02`, `EVIDENCE_HALF_LIFE_DAYS = 21`, `KNOWLEDGE_SCALE = 3`, `WEIGHT_DISMISS = 0.5`, `WEIGHT_RECOVERY_DAYS = 14`, `QUIET_HARD_MS = 90_000`, `QUIET_FULL_MS = 300_000`, `PREREQ_KNOWLEDGE = 0.3`, `NOVELTY_FLOOR = 0.15`, `NOVELTY_DECAY = 12`); names are proposals, the assertion stands. Tests assert against the constants where they can, so a retune does not rewrite them, and against the spec's quoted figures (about a quarter, about 80 %) with a tolerance where the spec states a rounded figure.
- Data: `apps/studio/src/copy/tips.ts` tested in `apps/studio/src/copy/tips.test.ts`, modelled on `copy/help.test.ts` (its `{{ui:…}}` known-label check) and `copy/gestures.test.ts`.
- Store: `apps/studio/src/chrome/chrome.test.ts` (exists; extended). localStorage stubbed per test (`localStorage.clear()` in `beforeEach`); the corrupt cases write raw strings under the operator's key.
- Components: jsdom beside the component (`organisms/TipCard.test.tsx`, `pages/SettingsPage` tests, `pages/HelpPage.test.tsx`). `motion/react` is used as shipped; assertions are on DOM state after `act`, with fake timers (`vi.useFakeTimers()`) for the clock. Hover via `userEvent.hover`/`unhover`; focus via `userEvent.tab`.
- Page tests: `apps/studio/src/pages/beta11.test.tsx` (`render(<App />)`, `createFakeHost()`, `fake.seed(demoLibrary(), [demoRecipe()])`, `setHostTransport(fake)`, `useNavStore.setState({ route: HOME, … })`; Play state through `?fake&play=` fixtures as the beta.10 page tests do).
- e2e: `e2e/specs/tips.e2e.ts` (Windows, tauri-driver), own `org.questiongame.e2e` data folder only.
- Names for the report seam: `tipMoment(moment)` (call sites), `tipLearned(skillId)` (gesture handlers and actions). Both write to the chrome store through the engine and are no-ops when tips are off for `tipMoment`, but **`tipLearned` still records** when tips are off (knowledge is kept so turning tips back on is not a reset).
- Helper formulas used in rows: `k(e) = 1 − exp(−e/3)`; `fade(e, d) = e · 2^(−d/21)`; `novelty(x) = 0.15 + 0.85 · exp(−x/12)`.

## Review focus (failure modes no row covers)

1. **The tip shows at the wrong time because the Play state arrives late.** At boot Studio has no `play-state` yet: a first-launch tip could appear over a Play that is already running (an app restart during a show, the host holding a `playing` Play). Rows 75–88 pin the engine and a mounted Play, but not the window between the shell mounting and the first `play-state` event. The build must treat "play state unknown" as blocked, and a manual check is a restart mid-Play on the real app.
2. **Two Studio windows, one operator.** The Statistics window (`stats`) is Studio on another display; if it mounts the shell it can report moments and show a tip on a projector or capture. Rows 154 and 203 don't cover a tip drawn in the Statistics window or the Viewer. Look at which webview labels run the tips and that Stage and `stats` never show a card or report a moment; and that two windows writing the same localStorage key do not clobber each other's evidence.
3. **Time is the operator's wall clock, and it lies.** Laptops sleep for days, clocks are changed, a `Date.now` jump is not a `Δdays` of 21. Rows 15, 16, 50 and 58 cover jumps in the engine, but not suspend/resume with the quiet window mid-run, or a daily cap keyed to a local date after a time-zone change on a travelling operator. Skim the clock injection: every read must go through it, with no stray `Date.now()` in `TipCard` or the store.
4. **Focus and keyboard collisions.** The tip does not take focus, but `Esc` while it has focus must not also close the dialog or editor behind it, and Control's single-key shortcuts (T, Enter, R, S, A, 1–9) must still fire while the card shows and the operator has tabbed into it (`ignoreInputs` does not cover buttons). Rows 119–121 prove the card, not the hotkeys around it. Check on the real app with a card visible: press `Esc` in an open editor, and a Control letter after clicking *Got it*.
5. **Copy that is true on one platform.** Tips show `{{key:…}}` caps and gestures that differ on macOS (Ctrl vs Cmd, the key labels) and the title-bar setting tip depends on the platform. Rows 129 and 180 check parsing, not that the Mac text is right or that a Windows-only tip is withheld on macOS. Also a long Romanian-keyboard or OS-scaled-font card running over *Got it* (row 137 is the only guard). A person on a Mac should read each tip once.

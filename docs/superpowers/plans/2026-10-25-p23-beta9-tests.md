# P23 (beta.9) — test list

Source: `docs/superpowers/specs/2026-10-25-p23-beta9-design.md`. Tests are written first, then the build.

Conventions followed
- Host: `crates/host/tests/<name>.rs`, `CatalogService::open(CatalogLocation::Memory)`, ids `q1..q5` (difficulty 10..50), `d1` History / `d2` Science, helpers `edit(&c, &[ids], BulkEdit::…)`, `members(&c, "d1")`, `domain(&c, …)`, `get_q(&c, …)`; names in the `b30_…` style (prefix `m<N>_`); property tests as in `round_invariant.rs`.
- Studio page tests: `apps/studio/src/pages/beta<N>.test.tsx` style — `render(<App />)`, `createFakeHost()` + `demoLibrary()`/`demoRecipe()`, `setHostTransport(fake)`, `useNavStore.getState().go({ tab, domainId })`, `findByRole`/`within`, hooks like `[data-bulk-strip]`, `useNoticeStore`, `useChromeStore.setState({ listState: {} … })`. Component tests sit beside the component (`LibraryList.test.tsx`, `BoardSection.test.tsx`, `ListControls.test.tsx`, `ImportQuestionsDialog.test.tsx`, `compact-chrome.test.tsx`). Text tests in `packages/text/src/index.test.ts`.
- New files: `crates/host/tests/beta9.rs`, `apps/studio/src/pages/beta9.test.tsx` (drag, status bar, template, search-in-pages), `apps/studio/src/organisms/StatusBar.test.tsx`. Everything else extends an existing file.

jsdom limits (what is asserted instead)
- jsdom has no layout: no real `position: sticky`, `overflow`, heights, scroll, or `IntersectionObserver`. Rule: assert (a) the class / `data-*` that carries the rule (as `compact-chrome.test.tsx` does with `h-9`), (b) DOM ancestry (inside / outside the scroller element, inside the domain's own container), (c) stuck state by a stubbed `IntersectionObserver` (`vi.stubGlobal`, keep the callback, call it with `[{ isIntersecting: false }]`). Pixel budgets are asserted as a sum of shared height constants; real measurement is in the manual/e2e list at the end.
- Drag: dnd-kit pointer sequences are unreliable in jsdom. Unit-test the drag model (a pure plan: items, mode, target → host call + chip text), plus page-level tests that fire `pointerdown / pointermove / pointerup` and, where jsdom blocks that, invoke the DnD context's `onDragStart/Over/End` handlers directly (as `SortableList.test.tsx` does).

## Studio — the highlighter (§1) — `packages/text/src/index.test.ts`

19. `highlight wraps each matching word prefix in <mark>` — `<Text highlight="ist">Istoria artei</Text>`: one `mark`, `textContent==='Ist'`; whole text still `Istoria artei`.
20. `highlight is case-insensitive and keeps the original casing` — query `ISTORIA` on `Istoria` → mark text `Istoria`.
21. `highlight ignores diacritics both ways` — `Pamant` on `Pământ` → one mark `Pământ`; `Pământ` on `Pamant` → one mark; `soim` ↔ `Șoim`; `ț`/`ţ` forms.
22. `highlight offsets survive diacritic folding` — text `Țara Pământ` and a decomposed `Â`, query `pam`: the mark covers exactly the first word characters, and the node's total `textContent` equals the input.
23. `highlight marks by word prefix, never mid-word` — `ist` on `Mistic Istoria`: exactly one mark, `Ist` of `Istoria`.
24. `highlight marks every word of a multi-word query` — `capitala franta` on `Care e capitala Frantei?` → marks `["capitala","Frant"]`, in order.
25. `highlight overlapping terms never nest` — `is ist` on `Istoria`: one mark, no `mark mark`.
26. `empty / blank / missing highlight is plain text` — `""`, `"   "`, `undefined`: no `mark`, and the markup equals the no-prop render.
27. `highlight treats regex metacharacters literally` — queries `c++ (a)`, `[x`, `\` do not throw; `c++` marks `c++` in `c++ basics`.
28. `highlight with no hit renders no mark` — query `zzz`.
29. `highlight with transition swap/count renders the text without error` — documented as ignoring highlight.
30. `mark uses the quiet accent tint and no text colour` — class contains the accent-tint class (e.g. `bg-accent/20`), no `text-*` colour class, `mark.style.color===''`.
